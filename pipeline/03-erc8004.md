# 03 — ERC-8004 identity và quality feedback

## 1. Deployment gate

ERC-8004 đang là draft; pin deployed ABI, address, chain, code/implementation hash và verified source trong manifest.
Candidate Fuji registries ở 00 phải được kiểm tra eth_getCode + verified source + read/write spike,
không gọi address "canonical đã xác minh" chỉ vì cùng vanity prefix.
Nếu candidate không có code/ABI cần thiết: ghi integration blocked, giữ S1 tool demo; không tự deploy rồi gọi canonical.
Self-deployed registry chỉ khi đổi manifest/claims rõ ràng. Không mix hai registry sets trong cùng identity.

Nguồn chính: [EIP-8004](https://eips.ethereum.org/EIPS/eip-8004),
[contracts và ABIs](https://github.com/erc-8004/erc-8004-contracts).
ABI thực tế quyết định cách gọi; nếu khác spec, ghi rõ deployed version thay vì tự chế hàm.

## 2. Wallet map và registration

O = mission/guard owner, MetaMask; A = agent key, đăng ký/own NFT; S = tool seller.
O != A; O không là NFT-approved operator; seller không nhận payment vào cùng ví payer.
A register identity một lần, ghi agentId, register tx, tokenURI, getAgentWallet và owner đọc lại.
agentWallet mặc định phải được kiểm tra trên registry thật, không suy từ metadata.
Nếu cần bind wallet khác dùng setAgentWallet đúng proof của deployed registry, không chỉ đổi JSON.

Registration JSON: type EIP registration-v1, name/description/image, services, x402Support, active,
registrations đúng chain/registry/agentId, supportedTrust phù hợp.
Host agent.json ở raw immutable commit URL hoặc static file thực sự trả JSON, không dùng GitHub HTML blob page.
Sau register biết agentId thì cập nhật file và setAgentURI nếu cần; không đoán ID trước khi minted.
Public metadata không có private key/token/private mission result.

## 3. Feedback eligibility và interface

Feedback đánh giá agent hoàn thành mission, không phải seller reputation.
O xác nhận deliverable đã nhận và ít nhất một ToolOperation SETTLED có receipt verified thuộc mission.
Một paid operation không tự chứng minh mission complete; completion được owner ký/confirm,
app persist completedAt + result hash và deduplicate một feedback/mission.
Mission có thể expired/closed khi owner hoàn tất review; read/feedback authorization vẫn dùng owner challenge (05).
MVP tag1=starred, tag2=demo-client, value 0–100 và valueDecimals=0.
Không dùng successRate từ tập chỉ gồm call thành công.

Interface dự kiến, phải khớp deployed ABI:
```solidity
function register(string calldata agentURI) external returns (uint256);
function getAgentWallet(uint256 agentId) external view returns (address);
function giveFeedback(uint256 agentId, int128 value, uint8 valueDecimals,
    string calldata tag1, string calldata tag2, string calldata endpoint,
    string calldata feedbackURI, bytes32 feedbackHash) external;
function getSummary(uint256 agentId, address[] calldata clientAddresses,
    string calldata tag1, string calldata tag2)
    external view returns (uint64 count, int128 summaryValue, uint8 summaryValueDecimals);
function readFeedback(uint256 agentId, address clientAddress, uint64 feedbackIndex)
    external view returns (int128 value, uint8 valueDecimals, string memory tag1,
        string memory tag2, bool isRevoked);
```
Nếu cần list chi tiết dùng readAllFeedback theo ABI pin; không có getFeedback(agentId) suy đoán.
Owner/operator NFT tự feedback bị reject; đó là giới hạn self-feedback, không phải chống Sybil.

Flow: O ký completion/feedback intent qua challenge bind mission, resultHash, agentId và value;
app prepare public feedback JSON, O gọi giveFeedback bằng MetaMask, backend record confirmed event/index.
Backend không ký feedback bằng A. Chuẩn không enforce một feedback/mission; app enforce dedup,
và reconciles event nếu response mất trước khi cho owner gửi lại.
getSummary không tự loại feedback ngoài app: UI phân biệt raw registry aggregate với app-verified mission feedback.
Trusted client list có nguồn rõ (ví O demo), không quảng cáo công chúng độc lập.

Feedback JSON gồm mission reference, client O, deliverableHash, paid operationId,
payment proof payer A/payTo/token/chain/nonce/tx và score; keccak256 đúng UTF-8 file bytes.
Không nói O trực tiếp đã trả payment nếu payer thực tế là A được O cấp ngân sách.
Proof chỉ chứng minh payment và linkage do app/owner xác nhận, không tự chứng minh answer quality.
Feedback file công khai chỉ dùng demo data đã được owner chọn publish, không dump result riêng.

## 4. Display, tests và fallback

Dashboard đọc agentId/URI/wallet, count+summary theo client/tag filters.
count là số feedback entries, không phải số mission/call thành công.
Nếu trusted list rỗng, hiện "chưa có trusted client"; không crash.
S1 chỉ identity display nếu spike đạt; chưa feedback thì không giả score.
S3: live register/read, O feedback sau completion, self-feedback negative test, summary đúng ABI,
duplicate event/mission, unauthorized feedback app, forged payment proof đều theo E-series ở 06.
Không tự tăng cap/allowlist vì reputation. Validation registry và Sybil resistance ngoài MVP.
