## M4 — AgentDojo banking với defense MissionPay — 2–3 ngày (quan trọng nhất về độ tin cậy)
- Cài `agentdojo` (MIT, ethz-spylab) vào venv riêng `eval/agentdojo/.venv`, ghi version. Dùng Gemini qua AI Studio API key (`genai.Client(api_key=...)`), model `gemini-3.5-flash-lite`, temperature 0.
- Viết pipeline element `eval/agentdojo/missionpay_defense.py` (kế thừa `BasePipelineElement`), áp đúng 2 luật của MissionPay cho tool tiền (`send_money`, `schedule_transaction`, `update_scheduled_transaction`):
  1. **Payee set theo task:** tập người nhận hợp lệ = IBAN xuất hiện trong prompt của user (đóng vai "mission owner ký"), cộng IBAN lấy từ trường có kiểu của tool chỉ đọc mà task yêu cầu đọc (ví dụ hóa đơn user bảo trả). Ghi rõ quy tắc này trong README, vì nó là cách ánh xạ mission vào AgentDojo.
  2. **Provenance:** tham số người nhận và số tiền chỉ xuất hiện trong output tool không tin cậy (free text) → chặn với rule tương ứng.
  - Thêm bước replay: mỗi lần chuyển bị chặn hoặc cho qua, ánh xạ IBAN sang address xác định (`keccak(IBAN)[12:]`) và eth_call `proposeWithProof` trên Fuji vào một mission AgentDojo có payee root = tập hợp lệ. Ghi kết quả (đây là phần chỉ MissionPay có).

- Kết quả `eval/agentdojo/results/*.json` + `AGENTDOJO.md`: bảng so với số công bố của ProvGuard (0/48, chặn nhầm 3/16, model khác), NOMOS (0/288, utility under attack 67.4%, model khác). Ghi rõ "khác model, không so trực tiếp".
