How a payout is decided

Three parties, and only one of them can be talked into anything.

The owner signs a mission

Budget, deadline and the exact payees, signed by the owner (passkey approval supported). The payee list is stored on-chain as a Merkle root.

The agent proposes

The agent reads invoices and web pages, so it can be fooled. It can only propose a payment, with a proof that the payee is on the list.

The contract decides

GuardedTreasury checks the proof and the caps. Anything else reverts. Our server holds no owner key.

What it does not do yet

  • 8 of 128 replayed attacks got through. In all of them the user’s own prompt named the attacker as the new payee.
  • The owner can reset a mission to allowlist mode. The reset is public on-chain.
  • Cross-chain spending (ICM) is tested locally only.
